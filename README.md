# QiMeet

QiMeet 是可自行部署的活动报名与签到工具。一个管理员管理多场活动，配置各自的报名表、开放时间、签到环节和现场二维码。活动管理、表单版本、名单导出和运营数据都在同一个后台。

## 本机运行

需要 Node.js 24.11+（24 系列）、pnpm 11 和 MySQL 8。

```sh
git clone https://github.com/OrangeZh1/QiMeet.git
cd QiMeet
```

创建空数据库及项目专用数据库用户，将 `.env.example` 复制为 `.env`，填写数据库、网页入口和两把各自生成的随机密钥。

```sh
pnpm install --frozen-lockfile
pnpm db:migrate
```

临时设置 `QI_ADMIN_PASSWORD` 后运行 `pnpm admin:set` 创建或重置唯一管理员。账号默认 `admin`，也可通过 `QI_ADMIN_USERNAME` 指定。初始化密码至少 12 个字符。设置完成后从当前终端环境移除密码变量。可运行 `pnpm demo:seed` 创建一场示例活动。

```sh
pnpm dev --host 127.0.0.1 --port 3086
```

后台入口是 `http://127.0.0.1:3086/admin`。报名和签到链接使用 `QI_ORIGIN`，现场使用要为它配置手机可访问的 HTTPS 域名。

### 局域网开发预览

将 `QI_ORIGIN` 临时设为本机局域网 IPv4 地址及开发端口，并让开发服务监听 `0.0.0.0`。以下为 PowerShell 示例，启动前替换其中的 IP：

```powershell
$env:QI_ORIGIN = 'http://192.168.1.10:3086'
pnpm dev --host 0.0.0.0 --port 3086
```

同一局域网的设备用该地址打开活动页面。本机仍可用 `localhost:3086` 或 `127.0.0.1:3086`，生成的签到码会指向 `QI_ORIGIN`。HTTP 私网地址仅供开发预览使用。

### 客户端账号

根路径进入活动列表。客户端用邮箱或中国大陆手机号验证码注册并设置密码，后续可用密码或验证码登录。报名、查看具体报名记录及签到需要登录。微信扫码使用开放平台网站应用，首次授权建立账号，后续授权登录同一账号。

- 在「站点设置 → 邮箱配置」填写 SMTP 服务器、端口、发件邮箱及认证信息。465 使用直接 TLS，其他端口要求 STARTTLS。
- 在「站点设置 → 短信配置」选择阿里云或腾讯云。阿里云模板的验证码变量为 `${code}`，腾讯云模板的验证码占用第一个变量 `{1}`。同一时间启用一家服务商，切换后会保留已保存的两家配置。
- 后台保存后立即生效，密钥和 SMTP 密码使用 `QI_DATA_KEY` 加密保存。尚未在后台保存的配置继续读取 `.env` 中对应的 `QI_SMTP_*`、`QI_SMS_PROVIDER`、`QI_TENCENT_*` 和 `QI_ALIYUN_*`。
- 微信开放平台需要审核通过的网站应用和 HTTPS `QI_ORIGIN`。在「站点设置 → 基本设置」填写 AppID、AppSecret 并启用扫码登录。原有的 `QI_WECHAT_APP_ID` 和 `QI_WECHAT_APP_SECRET` 仍可作为默认配置。回调路径为 `/api/account/wechat-callback`，应用授权回调域应与 `QI_ORIGIN` 的域名一致。
- 「站点设置 → 基本设置」也可选择开放手机号、邮箱登录与注册，并维护客户端登录标语和封面。「站点设置 → 协议管理」提供用户协议与隐私政策的 Markdown 编辑与预览。来宾可先阅读协议，再勾选同意并提交登录或注册。
- 邮箱、手机号、微信登录各自代表独立账号。使用相同登录方式可跨设备访问对应的报名记录。历史报名可以在登录后凭原凭证找回并关联。用报名姓名和手机号找回时，可查看受限状态和签到。

- 通过手机号验证码注册时，注册号码自动成为已验证的联系手机号。后台录入或缺少验证记录的号码先通过验证码确认。来宾可在「我的 → 个人资料 → 联系方式」验证或更换联系方式，登录继续使用原注册方式。

## 数据与现场操作

- 封面和头像都从后台素材库上传或选用。一场活动可以为来宾页配置最多 8 张封面并调整轮播顺序。素材在被已发布活动用作封面时可通过公开图片地址读取。
- 「站点设置 → 基本设置」统一设置各活动页面及签到投屏的版权与备案号。可在后台「帮助中心」维护客户端的常见问题。
- 活动发布后，后台可下载报名二维码或复制链接。扫码会打开该活动的报名表。
- 在活动的「报名表 → 报名通知」开启报名成功短信。在字段属性可指定收件手机号和姓名。优先使用表单指定的手机号，其次使用找回绑定号码或表单唯一手机号字段；表单未填写时使用个人资料中已验证的手机号。填写的收件号码与已验证号码不一致时，报名照常保存，回执会提示短信未发送。
- 短信配置只需填写一个已审核的报名通知模板，按实际正文选择「无变量」或「姓名与活动标题」。后者使用表单指定的短信姓名，未指定时取找回绑定的姓名，活动标题来自活动设置。阿里云变量为 `${name}`、`${activity}`，腾讯云依次为 `{1}`、`{2}`。缺少可用姓名或活动标题超过 35 字时，报名照常保存，回执会提示短信未发送。
- 每场活动支持固定和动态二维码，可以按签到环节单独配置。固定码可以打印和重发。动态码每 30 秒更新，有效期 90 秒。
- 在后台编辑签到环节时可开启「允许手机签到」。开放后，来宾登录并验证报名，在签到时段内可从活动详情或报名记录直接签到。
- 表单字段可以重复添加、复制、排序或移除。选择文件或图片字段时，可以配置一项接收 1 至 10 个附件。保存生成新版本，已提交报名按原版本查看、修改和导出。身份证号与报名附件加密保存。普通导出对身份证号脱敏，完整导出会登记记录数和时间。用表格编辑器打开完整号码时，将相应的 CSV 列按文本导入以保留位数。
- 数据库和加密密钥应分别保管和备份。迁移执行 `pnpm db:migrate`。应用实例使用一个 Node 进程和 MySQL 实例，反向代理需要允许带上传的请求达到 21 MiB。仅当代理清理并重设客户端 IP 请求头时启用 `QI_TRUST_PROXY=1`。

同一浏览器可通过报名会话直接查看对应活动的记录。可在表单中将姓名和手机号绑定为找回字段，也可仅使用专属报名凭证。

## 开发验证

在运行中的独立开发数据库和开发服务上，临时设置 `QI_TEST_ADMIN_PASSWORD`，运行 `pnpm test:flow` 可验证报名、找回、编辑、附件、签到和导出。测试使用独立活动及合成数据，完成后回收自身记录。

在本机独立数据库 `qimeet_delivery_test` 上完成迁移并初始化管理员，启动指向该库的开发服务。临时设置 `QI_TEST_ADMIN_PASSWORD` 后运行 `node --env-file-if-exists=.env --test test/delivery-settings.mjs`，验证短信和邮件配置保存、密钥保护和停用短信。
